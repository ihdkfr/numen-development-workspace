# Plan move, 13 October 2026

> **Update, later on 13 Oct:** the plan was then reordered into 14 new phases with 211 tasks, and task ids changed from `S01.01` to `T01.01` style, with the S ids kept as aliases. See `docs/PLAN_REORDER.md`. This file still describes the move itself.

The owner asked for every task and phase in NUMEN to be wiped and the Soul Survival plan moved in, in chronological order ("i want all the tasks and phases wiped so we can put ours in"). This file records how the site worked before, what changed, and what was deliberately left alone.

Two bugs found on the way: `combatDetail` used an undefined `LIB_KIN` (it crashed when a combat design had related systems); fixed to `LIB_KINDS`. The project-wide plan text called itself "independent of the existing project", which no longer applies.

## 2. What changed

- **The plan.** `data/plan-data.js` (14 phases, 182 tasks, 78 owner decisions, 18 Combat & VFX records) and `data/codex-data.js` (33 sections) replace the two embedded blobs. Images are in `plan-assets/`. Sources: the Claude plan tracker (every task, subtask, note and image), roadmap v5 from the game repo (every batch, with tasks, acceptance, files, don'ts and Claude Code prompt), the game repo's contracts and owner answers, the ChatGPT handover "Life of a Soul Reaper" (12 Oct) and the NUMEN 12 Oct approvals (A01 to A05, C16 to C40).
- **New ids.** Tasks are `S01.01` and up. Old `task:01.01` records can therefore never attach to a new task by accident.
- **Built work.** Tasks have a starting status from the plan (`seed_status`). Work that exists in the game but has not been played and approved sits in **Needs review** (done means played). Plan subtasks become the task's starting checklist; the first edit saves them into the team record.
- **Custom phases and tasks.** New custom phases save to `meta:phases:ss`; new custom tasks carry `plan: 'ss-2026-10'`. The old `meta:phases` and untagged custom tasks are shown on the Archive page instead of the roadmap.
- **Overlays removed.** The three overlay UI scripts are deleted and `legacy-plan.js` moved to `archive/legacy-plan-2026-10-12.js` (not loaded). Their job (showing the original plan inside the roadmap) is done by the plan itself now. The new code is one commented section in `index.html`, not another overlay file.
- **Archive page.** Lists every team record that no longer matches a task (with its notes, checklist, links, history and files), the previous blueprint (`archive/numen-blueprint-2026-10-12.json`: all 20 phases, 281 tasks and the old codex), the original SoulSurvival plan (`docs/legacy/`), old custom phases and deleted ids.
- **Combat & VFX.** Seeded with the real Standard Cero record (lock, the 29 timeline rows, completion evidence, outstanding shake, sound and performance work, the full CERO_LOCK and CERO_TIMELINE text) and the beam, Kido, movement and power records. Editing one saves a team copy under the same id.
- **Claude build brief.** Rewritten for the Soul Survival repo: steps, acceptance, applicable owner decisions, notes, and the repo's standing rules.
- **One guard.** In cloud mode a team member (not the owner) editing a task the plan marks approved gets a clear message instead of a database error, because the server treats the first save of such a task as a new approval.

## 3. What did not change

- The address, the repository and the Cloudflare deployment.
- `supabase/initial_schema.sql`, the database, its policies and functions. No row was read with elevated rights, written, migrated or deleted.
- Sign-in, team creation and joining, invitations, roles, owner-only approval, comments and notes, attachments, ideas, combat designs, activity, search, workshop, backup and import.
